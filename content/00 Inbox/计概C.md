# 环境准备

想必在在计概的第一节课，老师/TAs应该都向大家介绍过编程需要的软件。但在这里不妨重新聊一聊这个问题[^1]

对于任何编程行为，除了编程语言本身以外，我们都需要掌握两个要素：**工具**和**环境**

> [! ]
> **工具** 用来编写和运行程序的软件工具。它们帮助我们更高效地达成我们的目标，例如调试程序、管理项目等。
> 
> **环境** 我们编写、调试、运行代码的整个过程和条件，如操作系统、编程语言版本以及相关的库和框 架。一个良好的编程环境可以大大提高我们的工作效率；同时，我们写出的代码，最终也要运行在某个环境中。

一个可能不那么准确的例子：工具就像WPS/office，我们在上面编写文档/做PPT。而在移动端、PC端打开看到的文档格式可能都不一样，甚至不同用户在自己设备上看到的格式也不一样。这就是环境的差别
### IDE & EC范式

接下来为大家介绍IDE和EC范式。

**IDE（集成开发环境）**：编写、调试、测试代码所需的各种工具捆绑在一起，形成了集成开发环境。

典型的IDE：Visual Studio、Pycharm

![[Pasted image 20261007141336.png|678]]

比较适配于Windows系统，下载免费的Community版即可（如果非要下IDE的话）

**EC范式**：E for Editor, and C for Compiler. 即编辑器 + 编译器的开发范式。（==Strongly Commended==)

常用编辑器：Visual Studio Code

![[Pasted image 20261007141901.png]]

实际上编辑器种类非常多，电脑上的记事本、WPS……都可以算作编辑器

编译器：把我们写的高级语言翻译成机器能理解的机器码。

**==Python语言没有编译器，没有编译器，没有编译器!!!请务必记住==**

~~我们说EC范式只是因为惯常用法~~ 

我强烈推荐大家使用EC范式（特指VS Code）而不是IDE。IDE本身是面向专业开发者用于开发大型项目的，对于学生来说过于“重”，且具有一定门槛，更不要提初学者了。而编辑器更加轻量化，在使用上没有门槛。同时VS Code 有良好的社区生态、丰富的插件、多样的主题外观（？）……

# 编程学习

 >[!什么是编程]
> 编程的本质是我们将我们的想法和逻辑，通过一定的形式化后形成==抽象的、可计算的==模型（即数据结构和算法）；随后，用特定的编程语言将这些模型转化为计算机可以理解和执行的程序。
> 
> 编程语言是我们与计算机交流的工具，它们有着各自的语法和语义，帮助我们更高效地表达我们的想法。[^2]

OK，说了那么多我们终于进入学习编程本身了。我打算对几种学习方式做一个“从夯到拉”排行榜。

- 夯：OJ刷题、拜AI为师
- 顶级：向老师/TAs请教问题
- 人上人：在油管/B站找公开课程学习
- NPC：老老实实上课
- 拉完了：报编程班、手抄代码

（仅个人主观排序，请勿当真，如有冒犯，敬请原谅）

Computer Science 永远需要通过实践进行学习的，知识上的不足往往会在报错中呈现，在debug中修复。当然每个班老师的要求不同，考试考勤要求都不太一样，请大家以实际情况为准。

当然作为初学者没有系统学习过Python的语法、数据类型等，就直接开始刷题是不现实的。建议大家想办法速通一下相关知识，然后边刷边巩固。跟着正课学的问题主要是进度太慢。

接下来聊一聊贵校计概C考试的风格以及基于此我们刷题时可以关注什么

贵校计概C机考，我印象中分为两种风格：一种是10道或更多的小学生编程题，逻辑非常简单，主要考语法；一种是5道题，题目难度依次递增，前3道很简单，T4T5难点主要在：

1. 有 corner case不容易找到，需要认真读题 

2. 需要根据复杂的题目要求，设计和维护一个/多个数据结构和对象，通常是字典（dict）。

接下来讲一讲我印象中
数据结构及其维护：
- 列表（list）：增删查改，排序（正序、逆序）
- 字典（dict）：同上，多次排序

```python
a = {'a':1, 'b':2, 'c':3, 'd':3}
# 先按value排序从大到小排序,若value相同则按key的字典序排序
```

一些操作：比如按某种格式print……

**==计概C考试不涉及算法==**

由于本人已经有大半年没有手写过Python了，更遑论Python机考了，因此对题目的总结一定是有缺漏且不尽准确的。具体的情况还等各位去研究。

贵校计概C笔试比较老旧，和往年题重合度比较高，占比不算很大，最好考前认真看看PPT和找往年题练习。

关于AI使用：对于初学者，直接“端到端”的让AI根据题目生成代码对学习可能是非常有害的，更建议在已经有了明确想法但不会实现时再去找AI帮忙。当然在大作业阶段，我们的精力可能更多聚焦在“我们为啥要这样干”，那“怎么干”的部分交给AI我想是合适的。
